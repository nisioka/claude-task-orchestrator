# タスクソースの切り替え

オーケストレータが読み書きするタスクの置き場は、**同時にひとつだけ**。
`TASK_SOURCE` で選ぶ（既定 `linear`）。

| ソース | 必要な環境変数 |
|---|---|
| `linear` | `LINEAR_PERSONAL_API_KEY` |
| `clickup` | `CLICKUP_PERSONAL_API_KEY` / `CLICKUP_LIST_WORK` / `CLICKUP_LIST_PRIVATE` |

**使わない側のキーは要求しない。** 移行の間は両方が `.env` に並ぶので、両方必須にすると
行き来のたびに2箇所を直すことになる。

2つを同時に読む案は捨てた。「どちらが正か」を巡回のたびに決めることになるため。

## ClickUp の準備

1. スペースを1つ作り、その中に**リストを2つ**作る（`work` と `private` に対応）。
   グループの分けかたは provider の裁量で、Linear ではラベル、ClickUp ではリスト
2. ステータスをスペースに設定し、名前を `~/.config/ai-orchestrator/workflow.json` に書く
   （`docs/workflow.md`）。**ClickUp は名前を小文字で保存する**ので、設定にもその綴りで書く
3. AI用のアカウントをワークスペースに招待し、そのアカウントのAPIキーを使う。
   `actor("ai")` はキーの持ち主、`actor("human")` は**それ以外のただ1人**。
   3人以上いると人間を特定できずエラーになる
4. リストIDは URL から取れる（`https://app.clickup.com/<workspace>/v/l/li/<listId>`）

## カスタム項目

タスクに名前付きの値を持たせられる。**一目で見たい・後から引きたい**もの用で、コメントとは
役割が違う。コメントは経緯、項目は現在地。

| 項目 | 型 | 誰が入れるか |
|---|---|---|
| `worktree` | text | オーケストレータが worktree を作ったとき（`src/cli/personal-field.ts`） |

ClickUp のリストに同名の項目を作っておく。**無い名前を書こうとすると落ちる。**
黙って捨てると、書いた側は保存されたと思い込み、気づくのは後で探したときになる。

```bash
npx tsx src/cli/personal-field.ts --id=<ISSUE-ID> --name=worktree --value=/abs/path
```

Linear にはイシュー単位のカスタム項目が無いので、`fields` を渡すと明示的に失敗する。
本文かコメントへ書くこと。

## ClickUp で気をつけること

**名前は全部小文字で保存される。** `PJ:ABC` として作ったタグは `pj:abc` として返る。
provider はタグの照合を小文字で行い、`ensureLabel` は**保存された側の名前**を返す。
ラベル名を比較するコードは大小文字を無視すること。

**ステータスの除外はAPIに無い。** `statuses[]` は許可リストしか作れないので、
`excludeStatuses` は取得後にこちら側で落としている。リストのステータス一覧から補集合を
計算する手もあるが、それは許可リストに戻る話で、ボードにステータスを足した日に黙って
対象から消える。

**説明文の素の `description` は平文への射影**でリンクもコード片もリスト記号も落ちている。
読むときは `include_markdown_description=true` を必ず付ける。

**説明文の空行は保存時に潰れる。** `<!-- company-linear-id: … -->` のようなマーカーは
次の行と繋がるが、テキストとしては残るので抽出は通る（実機で確認済み）。マーカーを
行頭に固定して読むコードを書かないこと。

**コメントは `comment_text` に平文 markdown で投稿する。** リッチブロックはAPIが200を返して
保存もされるが、**UIに一切表示されない**。表は書かない（生テキストで表示されるため）。

**カスタム項目の id はリスト単位。** 名前からは引けないので、`GET /list/{id}/field` で
名前 → id を解決してから `POST /task/{id}/field/{field_id}` で書く。名前の照合は小文字で行う。

**期日はワークスペースのタイムゾーンで読む。** ClickUp は終日の期日を現地 04:00 として
保存するので、UTC で日付を取ると1日早い日付になる。
