# CI の待ち方: ci-wait を1回だけ呼ぶ

push の後の CI は、**`ci-wait` を Bash の `run_in_background` で1回だけ呼んで待ってください。** 終わると
1回だけ通知が来て、その出力が CI の要約です。待つあいだに別の作業をするのは構いません。

```bash
npx tsx {{coreDir}}/src/cli/ci-wait.ts --repo=<owner/name> --pr=<番号>
```

PR の無いブランチは `--pr` の代わりに `--branch=<ブランチ>` を渡します。上限の既定は90分です。

**この指示は、引き継ぎや記憶に書かれた CI の待ち方より優先します。** 引き継ぎには CI の待ち方を書かないでください。

## しないこと

- sleep・until/while のループ・pgrep・自作の監視スクリプトで CI を繰り返し読まない
- Monitor で CI を見張らない。`gh pr checks --watch` と `gh run watch` も使わない
- `ci-wait` が走っているあいだに、CI の状態を別に読まない

## 結果ごとにすること

要約の1行目が `結果: <結果>` です。

- `success`: 次の作業へ進む
- `failure`: 要約の annotations とログの末尾をまず読む。足りないときだけ、そのジョブのログを読む
- `cancelled`: 取り消しは失敗ではない。新しい push や上限で止まったもの。要るなら再実行する
- `timeout`: **同じ push に対して、もう1回だけ呼ぶ。** 2回目も時間切れなら、それ以上待たずに引き継ぎを書いて終わる。要約の「終わっていない」の行を引き継ぎに写す
- `conflict`: コンフリクトしていて CI が走らない。解いて push してから呼ぶ
- `no-runs`: head に CI が1本も始まらない。CI の対象外のブランチか、CI を飛ばすコミット。待ち直さない
- `closed`: PR が閉じた。待つものは無い

head が途中で変わったら、`ci-wait` は新しい head に乗り換えて待ち続けます。ボットの push で終わったと読まないでください。

レビューボットの状態は1行だけ添えられ、終わりの判定には入りません。レビューのコメントは、CI が終わったあとに1回読んでください。
