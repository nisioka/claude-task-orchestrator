# 作業ログ: 捨てた道をその場で書く

実装・rebase・追従のどの子も、**試して捨てた方法をその場で1行ずつ書き足してください。** 引き継ぎの
「試して駄目だった方法」は、このログを写して作ります。

文脈が上限に近づいてから思い出して書くと、早い段階で捨てた道ほど抜けます。抜けた道には、次の子が
同じ順番でもう一度ぶつかります。入れ替えた意味が無くなるのは、たいていこの抜けのせいです。

## 置き場所

```
~/.local/state/ai-orchestrator/worklog/<子の名前>.md
```

`<子の名前>` は、起動時に付けられた名前です（`ai-impl-ABC-123--be` など）。前の子のログが既にあれば、
**最初にそれを読んでから**作業を始め、同じファイルに続けて書いてください。そこに書かれている道は、もう
試さなくて構いません。試し直すなら、前と何を変えるのかを先に1行書きます。

## 書く時機

**方法を1つ捨てたら、次の手を打つ前に書いてください。** 捨てたと決めた時点がいちばん理由をはっきり
覚えています。

書くもの:

- コマンドや修正を試して、狙った結果にならなかったとき
- 調べた仮説が外れたとき（「原因は X ではなかった。Y を見て確かめた」）
- 前提が違っていて方針を変えたとき

書かないもの:

- 成功した手順。それはコミットと報告に残ります
- 打ち間違いや、すぐ直したタイプミス

## 書き方

1つの道を1行で書きます。後から読む子が、同じことをもう一度試すべきかを判断できる書き方にしてください。

```
- <時刻> 試したこと: <コマンドや修正>。結果: <何が起きたか。エラーなら要の1行>。捨てた理由: <なぜ駄目か>。次: <代わりに選んだ道>
```

例:

```
- 14:20 試したこと: worktree で make setup。結果: ポート 5432 衝突で compose が起動せず。捨てた理由: 本体チェックアウトのDBが掴んでいる。次: PORT_OFFSET を付けて make 経由で起動
- 15:05 試したこと: 失敗したテストを個別に再実行。結果: 単体では通る。捨てた理由: 順序依存で、修正箇所の不具合ではない。次: 前に走るテストのフィクスチャを確かめる
```

エラー出力をまるごと貼らないでください。要の1行で足ります。ログは次の子が丸ごと読むので、長いと
その子の文脈を食います。

## 引き継ぎを書くとき

引き継ぎの「試して駄目だった方法」には、このログの行を写してください。要約して短くするのは構いませんが、
**行を落とさないでください。** 写したうえで、ログのパスも引き継ぎに書いておきます。

ログが空なら、「試して駄目だった方法: なし」と書きます。空欄にはしません。
